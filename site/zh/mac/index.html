02 / 搜岗

三个渠道。
一份认真筛过的清单。

只读子 Agent 并行初筛，主 Agent 汇总发现，再逐一终审。

Terminal — Claude Code · lead agent

主 Agent › 每个子 Agent 负责一个渠道。读完整职位描述，核实匹配度，返回候选清单。

  • ├
    job-scout · LinkedIn只读 → reports/scout/…-linkedin.json
  • ├
    job-scout · Indeed只读 → reports/scout/…-indeed.json
  • └
    job-scout · 公司 ATS只读 → reports/scout/…-ats.json

我会终审候选，再检查岗位与公司是否重复。
jt seen · jt company

shortlist.json · 演示片段
{
  "channel": "linkedin",
  "source": "scout",
  "shortlist": [{
    "company": "Alpine Ski House",
    "role": "Senior React Engineer",
    "verdict": "recommend"
  }]
}

子 Agent 不投递、不发消息、不打开未读聊天。浮窗 JSON 是使用示例候选的简化片段。

03 / 由你批准

替你起草。
由你拍板。

对象与原文放在一起审阅。除非你已预先批准该动作类型，否则每次对外动作都先等你同意。

Terminal — Claude Code · 等待批准

Claude › 这是等你批准的回复原文。

T2 · 首次回复主动联系的招聘者

收件人：Example Co. 招聘团队 · 邮件

Example Co. 招聘团队，你们好。感谢联系我介绍前端工程师岗位。方便分享一下公司或客户、团队规模和工作安排吗？如果合适，我很乐意提供简历。

Claude › 把这段原文发给这位收件人吗？

你 › yes, send it（可以，发送吧）

这次批准仅针对该收件人与这段原文。核实送达后，才会记录为已发送。

T2 回复示意，使用占位公司，不包含个人经历声明。人参与每一步：起草 → 审阅 → 批准 → 核验送达。

05 / 周五复盘

看懂这一周。
调整下一周。

哪些有效，哪些还缺证据，接下来改什么。最多三项调整，每项都看依据，并约定复查时间。

Terminal — 每周复盘

$ python3 bin/jt.py funnel --by source

演示数据 · examples/tracker.json 的实际计算输出

Source            Applied  Replied  Reply rate  Interviews  Rejected
(unrecorded)            8        0          0%           0         1
Total                   8        0          0%           0         1

Claude › 下次复盘前，先做三项调整：

  1. 先补已知来源。8 条记录的来源都未填写，现在还不能给渠道排优先级。
  2. 按证据补齐里程碑。Northwind 状态为面试中，但未记录面试日期；这里的零不代表没有面试。
  3. 调整搜岗精力前，用 --since 比较观察时间相近的批次，再看 --by platform。下周五复查；本示例样本小且记录不全。

这是当前跟踪器的实际计算，不是效果宣称：8 条记录包含一条草稿；回复和面试为零，是因为没有填写里程碑字段。来源与投递平台不是同一回事。
